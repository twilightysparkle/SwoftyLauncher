# 1.10.27

Swofty Launcher for F1 25 1.10.27 refuses mods made for another F1 game that replace F1 25's packed game data, builds your addons' team logos in any game folder only administrators can change, and names the damaged file when a build stops on a damaged archive.

## Fixes

- The launcher no longer installs or imports a mod made for another F1 game, such as one with a `2020_asset_groups` folder, that carries its own `game.dat` or `game.daf`, the files that hold F1 25's packed game data. F1 25 can't start with those files replaced. Such an addon already installed has all its files left out of the build, and a build warning names it and says to turn it off. The build also leaves out any addon's `file.put` to `game.dat` or `game.daf`.
- When F1 25 closes itself as it starts, before it sets up its graphics, while an addon that carries its own `game.dat` or `game.daf` is on, the crash screen now names that addon and says to turn it off.
- The crash screen no longer names ReShade, OptiScaler, Special K or an ASI loader in the game folder for a crash before F1 25 set up its graphics.
- Your addons' team logos and badges are now built when F1 25 is in a folder only administrators can change other than the default Program Files folder, such as `E:\Program Files\F1 25`. Before a modded session, the launcher checks whether F1 25 can create files in the folders it builds them in, and, run as administrator, opens up each one it can't. See [Game copies](/using/game-copies).
- When a build stops on an archive that does not decode, the error now names the file and what in it does not decode. For an addon's file it names the addon and says to turn it off or install it again; for a game file it says to verify or repair the game files; for a damaged backup of an original game file it sends you through the one-time setup again.
- When two addons on in the profile declare a conflict, **Play** now stops before anything is built, names both addons and says to turn one of them off on the Addons page.
- When the `swofty` command crashes before the game starts and before it says why, **Play** now says **the swofty command crashed** with its exit code, such as `0xc0000005`, and to reinstall the launcher with the installer. Your addons and settings are kept.
- Launcher updates now write each new file through to disk before they replace the launcher's folders.
- Fixed F1 25 sometimes not closing, or crashing as it closed, when it closed during startup while the core was still setting up its D3D12 hooks.
- The Addon Browser now leaves out only an addon version the launcher can't read, instead of the whole addon.

## Time Trial

- When the launcher could not load the Time Trial integrity module for a session, Time Trial is now blocked in game for that session. The main menu's Time Trial card reads **Unavailable: the integrity module did not load**, and the game says why. Start the game again with a working connection, or turn off Time Trial boards in the launcher to play Time Trial without the boards. See [Time Trial blocked](/std/systems/laps#time-trial-blocked).

## Under the hood

- Load-stall reports now have a section on what the game waits on between the title screen and the main menu: the boot route it waits on, its state and its raw bytes.
- When Send Logs cuts a `loader.log` over 5 MB, it now keeps up to 512 KB from its `stage: window` line, where addons load and install their hooks, as well as its start and end.
