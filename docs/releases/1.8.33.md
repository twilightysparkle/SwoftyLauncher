# 1.8.33

Swofty Launcher for F1 25 1.8.33 fixes a first-play setup reset that kept stopping on a locked folder and the Saves page listing another save's versions, and gives addons pause and resume events.

## Launcher

- Resetting the first-play setup, or putting the game folder back, no longer stops with "os error 32" when an empty addon folder stays locked. Addon helpers are stopped while the game folder is put back, and an empty folder that stays locked is left in place and logged. A locked folder that still holds files stops the reset as before.
- The Saves page lists the versions of the save the selected profile starts the game with. When the version you chose to restore isn't in the list, the page says so.

## For addon authors

- `game.pause` and `game.resume` fire when the game pauses and resumes, and the new `swofty/view.hpp` reads the pause state with `swofty::view::available()`, `pause_reasons()` and `paused()` ([events](/reference/std/events#pause-and-resume)).
- The event context's `player()` is the human's car while a session has cars, and `participants()` lists every car of the session ([events](/std/events)).
